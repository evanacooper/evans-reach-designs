What's happening
The score is submitted first and recorded as private feedback in its own right. Only after it's stored does the score decide what the customer sees next.
✓
Submitting the score counts. A promoter never has to write anything for their feedback to be captured — which is why the fast-track branch has no complaint box.
🔒
Both branches end at Google. The score changes how fast and how frictionlessly someone gets there. It never changes whether they're asked.
New capability: the form has no post-submit redirect or conditional field support today. The entire on-submit model is a single unused "show a message" action, and the renderer ignores it in favour of a hardcoded thank-you card.

Structural guards

Constraints that are impossible to configure wrong, rather than documented for someone to remember.

Compliance
⚠
The gating machine already exists in the codebase. A registered SQL segment filters customers to rating >= 9 AND rating <= 10, and the automation engine halts a flow when a segment check fails. 11 tenants have a row for it. Zero active automations reference it — so it has never fired, but nothing structural prevents someone wiring it up tomorrow.
🔒
One follow-up switch
The follow-up ask is a single boolean on the combined flow. There is no per-branch field to set, so "off for detractors, on for promoters" has no representation in the data model.
followUpAsk: boolean
✗ followUpAsk: { high, low }
🔒
Sentiment can't reach the ask
Segments feeding a Google stream are validated to exclude any predicate on a feedback score, complaint flag or incident record — rejected at save time, at both partner and tenant layers.
✗ nine-or-ten-feedback → Google stream
✓ recent-orders → Google stream
🔒
Symmetric cooldowns
Cooldowns take a duration and nothing else. They can't reference score, response content, or ticket state — so "hold the ask until the recovery ticket closes" isn't expressible.
🔒
Capped do-not-solicit
Manual exclusions stay available for legitimate cases. Bulk import is capped and each entry carries a logged reason, so the list can't quietly become a complaint-derived suppression list.
Bulk import cap
50 / import · reason required
Backlog conversion
One tenant has ~91 positive private responses collected before Google asks existed, and converting them will get proposed.
✗
A catch-up campaign to people who left good private feedback is textbook selective solicitation — the audience is defined by sentiment. The supported version targets everyone with a qualifying visit in the period, whether they responded, scored badly, or never replied. Same period, same visit criteria, no score filter. The 91 are included because they had visits, not because they were happy.

Structural guards stop the configurations we anticipated. Google conversion rate by score band catches the ones we didn't — if promoters convert far better than detractors, something is creating a friction gap we didn't design.
